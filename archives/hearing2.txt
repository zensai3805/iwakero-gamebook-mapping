# 仕様詳細化のためのヒアリング項目

## 1. パラグラフの記録粒度について

### 1.1 戦闘やダイスロールの結果の扱い
- 「戦闘に勝利した場合は10へ、敗北した場合は20へ」のような条件分岐はどう記録しますか？
- サイコロの目による分岐（「1-3なら30へ、4-6なら40へ」）はどう記録しますか？
- 実際に選んだルートのみ記録？それとも全ての可能性を記録？

回答：さいころの目ではなく、上の場合は勝利と敗北が選択肢ですね。可能なら全ての選択肢を記録した上で選んだルートを続きで記録したいですが、入力の手間が過度に増えそうであれば、選んだものだけに絞ったうえで、このパラグラフは全何パターンあるのかの数字だけ記録でもよいと思っています。


### 1.2 アイテムやフラグによる条件分岐
- 「鍵を持っていれば50へ、なければ60へ」のような分岐はどう記録しますか？
- アイテムの所持状態も管理する必要はありますか？

回答：鍵を持っている、持っていないが選択肢ですね。状態を記録する必要はありません


## 2. パラグラフの「状態」について

### 2.1 複数回訪問
- 同じパラグラフに複数回訪れることはありますか？
- その場合、訪問回数を記録する必要はありますか？
- 各訪問時の選択を個別に記録する必要はありますか？

回答：同じパラグラフに複数回訪れる可能性はありますが、訪問回数の記録は不要です。いわゆるリプレイ記録をつけたいのではなく、そのゲームブックの全貌の解明が目的なので、何度もプレイする中で、フロー図やマップを完成させていくイメージです。


### 2.2 パラグラフの方向性
- 一方通行のパラグラフ（戻れない）と双方向のパラグラフを区別する必要はありますか？
- 「戻る」という選択肢をどう扱いますか？

回答：戻るという選択肢はゲームでは明確にパラグラフの移動として実装されているはずなので、そこの混乱はないはずです。ただ、マップを出す際には、パラグラフとマップの位置が明確に1:1にならない可能性もあり、例えば「あなたは戻って北へまっすぐ進んだ」のような記載をどう記録するかは、要検討ですね。


## 3. マップ生成の詳細

### 3.1 マップに表示する情報
- テキストベースの2Dマップで表現したい情報は何ですか？
  - [ ] パラグラフ番号のみ
  - [ ] 部屋の種類（戦闘、宝箱、罠など）
  - [ ] 訪問済み/未訪問の区別
  - [ ] その他（具体的に：　　　　　　）

回答：フロー図が別であるので、パラグラフの番号のみで良さそうです。ただし、複数のパラグラフが同じ場所に紐づくる可能性があります。


### 3.2 マップの座標系
- マップ上のパラグラフの配置はどう決めますか？
  - [ ] 自動配置（アルゴリズムに任せる）
  - [ ] 手動で座標を指定
  - [ ] 選択肢の方向（北、南、東、西）に基づいて配置
- 東西南北の概念をマップに反映させる必要はありますか？

回答：自動配置が望ましいです。東西南北の概念の繁栄は必須ですね。自動が難しければ、手で記録しやすいフォーマットの確立が必要です。
