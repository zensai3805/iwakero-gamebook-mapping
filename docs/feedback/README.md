# フィードバック履歴管理

このディレクトリには、バージョン別のプレイテストフィードバックが保存されています。

## 📂 ディレクトリ構造

```
docs/feedback/
├── README.md                          # このファイル
├── PLAY_FEEDBACK_v0.2.0.md           # v0.2.0のフィードバック
├── PLAY_FEEDBACK_v0.2.1.md           # v0.2.1のフィードバック
└── PLAY_FEEDBACK_YYYY-MM-DD.md       # 日付別フィードバック
```

## 📋 ファイル命名規則

### バージョン別フィードバック
- **形式**: `PLAY_FEEDBACK_v[バージョン].md`
- **例**: `PLAY_FEEDBACK_v0.2.0.md`
- **用途**: 特定バージョンの総合評価

### 日付別フィードバック
- **形式**: `PLAY_FEEDBACK_YYYY-MM-DD.md`
- **例**: `PLAY_FEEDBACK_2025-07-05.md`
- **用途**: 継続的な検証結果

### 検証者別フィードバック
- **形式**: `PLAY_FEEDBACK_v[バージョン]_[検証者名].md`
- **例**: `PLAY_FEEDBACK_v0.2.1_Claude.md`
- **用途**: 複数のAI/人間による検証

## 🔄 フィードバック管理フロー

### 1. 新規フィードバック作成

**手動作成の場合**:
```bash
# テンプレートをコピー
cp templates/PLAY_FEEDBACK_TEMPLATE.md docs/feedback/PLAY_FEEDBACK_v0.2.1.md

# 実際のプレイテスト実行
./gamebook  # または各種CLIコマンド

# フィードバック記入
# （テンプレートに従って具体的な問題・改善点を記載）
```

**AI依頼の場合**:
```bash
# プロンプトをコピーして使用
# → AIが自動的にdocs/feedback/PLAY_FEEDBACK_YYYY-MM-DD.mdとして作成
```

**重要**: すべてのフィードバックファイルは必ず `docs/feedback/` ディレクトリに保存してください。

### 2. 最新フィードバックの参照
```bash
# 最新のフィードバックファイルを確認
ls -la docs/feedback/ | head -10

# 特定バージョンのフィードバック確認
cat docs/feedback/PLAY_FEEDBACK_v0.2.0.md
```

### 3. 比較・分析
```bash
# バージョン間の比較（問題の改善状況確認）
diff docs/feedback/PLAY_FEEDBACK_v0.2.0.md docs/feedback/PLAY_FEEDBACK_v0.2.1.md

# 問題の傾向分析
grep -n "⭐⭐⭐⭐⭐" docs/feedback/*.md  # 最高優先問題の抽出
```

## 📊 フィードバック活用方法

### 開発優先度の決定
1. **最新フィードバックの確認**: 直近の問題状況を把握
2. **⭐5段階評価の集計**: 最高優先問題を特定
3. **バージョン間比較**: 改善進捗の確認
4. **Issue作成**: フィードバックから具体的な開発タスクを抽出

### 品質向上のトラッキング
- **致命的問題の推移**: ⭐⭐⭐⭐⭐問題が解決されているか
- **ユーザビリティ改善**: 実際の使用体験が向上しているか
- **新機能の評価**: 追加機能が期待通り動作しているか

## 🤖 AI検証者向けガイド

### フィードバック作成時のポイント
1. **テンプレート厳守**: `templates/PLAY_FEEDBACK_TEMPLATE.md` の指標を必ず満たす
2. **操作回数の確保**: 最低実行回数の基準をクリア
3. **エッジケース検証**: 意図的なエラー発生と回復テスト
4. **具体的記述**: 再現可能なコマンド例と結果を明記

### 検証の網羅性チェック
- [ ] **自然なプレイ体験**: 実際のゲームブックプレイの流れを忠実に再現
- [ ] **具体的な冒険ストーリー**: 抽象的テストではなく物語性のある検証
- [ ] **ゲームシート管理**: 体力、アイテム、数値管理を実際に体験
- [ ] **条件分岐の実践**: 「もし○○なら」系の判定を実際に実行
- [ ] **想定外パターンの探求**: 開発者が予期しない使用方法を発見
- [ ] **複数視点での評価**: 異なるプレイスタイルや経験レベルを考慮

## 🔍 フィードバック分析コマンド

### 頻出問題の抽出
```bash
# 最高優先問題の一覧
grep -A5 "⭐⭐⭐⭐⭐" docs/feedback/*.md

# 改善要望の傾向分析
grep -A3 "💡 改善要望" docs/feedback/*.md

# 良好な機能の確認
grep -A3 "🎯 使用体験で良かった点" docs/feedback/*.md
```

### 統計情報の取得
```bash
# フィードバック数の確認
ls docs/feedback/PLAY_FEEDBACK_*.md | wc -l

# 問題の重要度分布
for star in "⭐⭐⭐⭐⭐" "⭐⭐⭐⭐" "⭐⭐⭐"; do
  echo "$star: $(grep -c "$star" docs/feedback/*.md) issues"
done
```
