# Issue駆動開発

## 開発方針

- **すべての作業はGitHub Issueとして管理**
- **Issueの冒頭にSPECIFICATION.md・DEVELOPMENT.mdの確認を必須**
- **IssueのCloseはPRで行う**

## 開発フロー概要

1. **Issue確認・作成**: → `docs/dev/issue-management.md`
2. **実装**: TDD実行（RED → GREEN → REFACTOR）
3. **PR作成**: → `docs/dev/pull-request-management.md`
4. **ユーザーマージ**: PRのマージは必ずユーザーが実行

詳細な手順は各専門ドキュメントを参照してください。
