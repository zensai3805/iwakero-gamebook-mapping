## 検証方法

**必須**: 実際にゲームブックを手に取った人間プレイヤーの立場で、**自然なプレイ体験をシミュレート**

### 🎮 ゲームブックプレイシミュレーション

**重要**: 単なる操作確認ではなく、実際のゲームブックプレイの流れを再現すること

#### 1. **冒険の開始**
- 新しいゲームブック作成
- 冒険記録シートの準備（体力、技量、運、所持金、アイテムなど）
- 段落1から冒険開始

#### 2. **自然なプレイフロー**
以下のような実際のゲームブックに登場する状況を含めて検証：

**📝 ゲームシート管理と記録**
- 体力値の増減（食事、戦闘、毒など）
- アイテムの獲得・消費・紛失
- 所持金の増減
- 技量や運の数値変化
- 特殊な状態（呪い、病気、能力向上など）

**⚔️ 戦闘・運試し・判定**
- 戦闘の勝敗による分岐
- 運試しの成功・失敗
- 技量判定、体力判定
- サイコロ判定の結果による選択

**🔀 条件分岐システム**
- 「もし○○を持っていれば△△へ」
- 「体力が□以下なら××へ」
- 「以前に◇◇を選んでいたら○○へ」
- 複数条件の組み合わせ

**🔄 複数回プレイ・異なる選択**
- 同じ段落で異なる選択肢を選ぶ
- 前回と違うルートを探索
- 行き止まりや死亡からの再開
- 隠しルートの発見

**❌ 想定外の状況**
- 記録の間違いや見落とし
- 段落番号の読み間違い
- 選択肢の選び間違い
- ツールの操作ミス

### 🤖 AI検証者向け：プレイシミュレーション指針

#### 自然なプレイストーリーの作成
```
例：火吹き山の魔法使いプレイ
1. 冒険開始 → 体力24、技量11、運10で記録
2. 村人との会話 → 情報収集、アイテム購入
3. 洞窟への侵入 → 松明の管理、道の選択
4. 戦闘発生 → 体力減少、戦利品獲得
5. 条件分岐 → 「鍵を持っていれば」で選択肢変化
6. 死亡・再開 → 異なる選択で再挑戦
```

#### 多様性と深度の確保
- **最低3つの異なる分岐ルート**を実際に体験
- **最低2回の失敗・再開**を経験
- **最低5つの条件分岐**を実際に判定
- **最低3つの数値管理**（体力、アイテム、所持金など）を実践

#### 想定外の使用パターンの探求
- 操作手順を意図的に変更
- ツールの限界を探る使い方
- 記録ミスからの回復方法
- 複雑な条件分岐での使用感

## 📝 記述ガイドライン

### 重要度評価の基準
- **⭐⭐⭐⭐⭐**: ツール使用を断念するレベルの致命的問題
- **⭐⭐⭐⭐**: 大幅にユーザビリティを損なう重要問題  
- **⭐⭐⭐**: 改善により体験が向上する問題
- **⭐⭐**: あると便利な改善
- **⭐**: 将来的な検討事項

### 問題記述のポイント
1. **具体性**: 実際のコマンドとエラーを記載
2. **再現性**: 他の人が同じ問題を再現できる情報
3. **影響範囲**: どのような場面で問題になるか
4. **実用性**: 改善案は実装可能で効果的か

### 良い例・悪い例

#### 良い例 ✅
```markdown
### 段落順序依存問題 ⭐⭐⭐⭐⭐

**問題**: 選択肢追加時に移動先段落が存在しないとエラーになる

**実際の体験**:
```bash
./gamebook choice 1 "洞窟に入る" 23
./gamebook select 1 1
# → エラー: paragraph not found
```

**影響**: 本を読みながらの自然な記録フローが完全に阻害される
```

#### 悪い例 ❌
```markdown
### 使いにくい

**問題**: なんか使いにくい

**影響**: 困る
```

### フィードバックの品質向上のために
- **プレイ体験の真正性**: 実際のゲームブックプレイの流れを忠実に再現
- **想定外の発見**: 開発者が予期しない使用パターンや問題を積極的に探求
- **具体的な物語**: 抽象的な操作確認ではなく、具体的な冒険ストーリーを通じて検証
- **複数視点での評価**: 初心者・経験者・異なるプレイスタイルの視点を含める
- **改善案の実用性**: 技術的実現可能性と実際の使用場面での効果を考慮

### 🎲 AI検証者への重要指示

#### 自然なプレイ体験の重視
- **ストーリー重視**: 単なる機能テストではなく、冒険の物語を作りながら検証
- **感情移入**: プレイヤーの感情（興奮、困惑、苛立ち、満足感）を意識した評価
- **想定外の歓迎**: 開発者が想定していない使い方や問題を発見することを重視

#### 多様な使用パターンの探求
- **異なるプレイスタイル**: 慎重派、冒険派、効率派、探索派など
- **様々なゲームブック**: 戦闘重視、謎解き重視、探索重視など
- **プレイ環境の違い**: 静かな部屋、移動中、時間制限ありなど
- **経験レベルの違い**: 初めてのゲームブック、熟練プレイヤー、ツール初心者など

#### 発見重視のアプローチ
- **問題の発見**: 「これは使いにくい」と感じる瞬間を詳しく記録
- **改善機会の発見**: 「こうだったら便利」と思う瞬間を詳しく記録
- **予想外の良さ**: 期待以上に良かった機能や体験を詳しく記録
- **限界の発見**: ツールの限界や制約を実際の使用で確認
